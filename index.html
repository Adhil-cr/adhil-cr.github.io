EXAMCELL AUTOMATION SYSTEM

// High-Integrity Examination Hall & Matrix Seating Engine

Problem

Manual examination seating across multi-department batches caused frequent subject collisions, underutilized hall capacities, and error-prone paper workflows during institutional examinations.

Solution

Built an automated matrix seating engine in Django & PostgreSQL that normalizes student enrollments into 1:1 subject records, enforces deterministic anti-cheating distribution, and produces verifiable PDF/Excel seating plans in seconds.

ARCHITECTURE HIGHLIGHT

Matrix Bench Allocation & Constraint Propagation: Models hall benches as discrete coordinate matrices (row × column × seat slot). Implements a dual-tier greedy allocation algorithm enforcing deterministic inter-department interleaving so no two adjacent students share the same exam paper while strictly respecting hall capacity limits.

PRODUCTION BACKEND FEATURED

CORE COMMERCE SERVICE

// Transactional Backend Engine with Strict Concurrency & Isolation

Problem

High-concurrency checkout spikes frequently cause inventory overselling, race conditions between simultaneous shoppers, and orphaned database states when cart sessions drop mid-payment.

Solution

Engineered a resilient Django commerce backend enforcing ACID database transactions with row-level locks, soft-deletion patterns for audit trails, and strict role-based access control between customer and administrative portals.

ARCHITECTURE HIGHLIGHT

Row-Level Lock Concurrency (SELECT FOR UPDATE): Leverages PostgreSQL row-level locks within atomic transaction blocks during inventory reservation, eliminating race conditions under simultaneous checkout attempts without the operational overhead of an external distributed locking service.

[Python 3.12] [Django REST] [PostgreSQL] [ACID Transactions] [Gunicorn] [WhiteNoise]
